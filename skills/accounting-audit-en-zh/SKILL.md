# 会计审计英文报表中译（accounting-audit en→zh）

## 何时用

- 用户手里有英文财报（10-K/20-F/年报/半年报/审计报告/附注），要中文版、要逐行讲解、要核数字。
- 用户要把审计底稿、管理层声明、准则条文（IFRS/IAS/ISA/ASC）读成中文。
- 用户在做跨境审计、境外上市、ACCA/CPA 英文科目学习，需要**术语一致**的双语材料。
- 不要用于：合同条款翻译（用法律类流程）、纯商务邮件（用邮件类流程）。

## 五分钟工作流

1. **判定文件类型与口径**
   - 是「报表本体」还是「附注/管理层讨论」？前者按行项目对齐，后者按段落翻。
   - 口径先确认：US GAAP / IFRS / 中国会计准则（CAS）。三者在科目名与列报顺序上不同，混用会错。
   - 单位先落定：`in thousands` = 单位千元、`in millions` = 单位百万元。**这是最高频的错**。

2. **结构对齐（先搭骨架，再填肉）**
   - 报表本体一律先抽成「行项目表」：英文科目 / 中文科目 / 本期 / 上期。
   - 报表类型识别与科目清单见 `references/statement-layouts.md`。
   - 附注按编号切段（Note 1、Note 2 …），每段一句英文一句中文，不做整段意译。

3. **逐条落地术语（禁止自创译名）**
   - 先查 `references/glossary.csv`（750 条：629 条教材术语 + 179 条报表行项目）。
   - 查不到时按顺序降级：① `references/statement-layouts.md` 的科目表 → ② 中国会计准则用语 → ③ 直译＋括号补英文原词。
   - 命令行查词：`python scripts/term_lookup.py "net realisable value"`，`--zh 坏账准备` 可反查。
   - 同一英文词全文只用一个中文，同一个中文也不要对应两个英文词（一致性 > 优雅）。

4. **数字与单位校验（必做，不可省）**
   - 抽取原文全部数字，与译文数字做差集；差集非空即视为**不合格交付**。
   - 括号＝负数：`(742,180)` = -742,180，不是正数。
   - 破折号 `—` 或 `-` 在金额列＝零，不要译成「无数据」。
   - 合计要验算：total assets = total liabilities + total equity；分部之和 = 合计。
   - 详见 `references/translation-rules.md`。

5. **交付**
   - 默认给**双语对照表**（左英右中），便于用户核对；只要中文时再给纯净版。
   - 附「术语一致性报告」：命中术语数、未按术语库处理的词、数字校验结果。
   - 附「不确定清单」：拿不准的 3–10 个词单独列出，请用户确认，不要藏在正文里。

## 输出模板（报表本体）

```markdown
## 合并资产负债表 Consolidated Statement of Financial Position
单位：千美元 (in thousands)　口径：IFRS

| English | 中文 | 2024 | 2023 |
|---|---|---|---|
| Cash and cash equivalents | 现金及现金等价物 | 128,450 | 102,340 |
| Trade receivables | 应收账款 | 96,200 | 88,100 |
| **Total assets** | **资产总计** | 1,284,500 | 1,102,340 |
```

## 输出模板（附注/段落）

```markdown
**Note 2 — Accounts receivable**
附注 2 — 应收账款

> Trade receivables are stated at net realisable value after deducting an allowance
> for doubtful accounts of $12,400 (2023: $9,870).
> 应收账款按可变现净值列报，已扣除坏账准备 12,400 美元（2023 年：9,870 美元）。
```

## 八条硬规则

1. **数字零容忍**：数字、百分比、股份数、日期全部逐字保留；千分位与负号括号照抄。
2. **术语锁定**：术语库有的词不许换说法。`provision` 在负债类＝「预计负债」，在所得税语境＝「所得税费用」，看上下文但仍在库内选。
3. **公司名/准则号不译**：`IFRS 15`、`ASC 606`、`ISA 700`、`PricewaterhouseCoopers` 保留原文。
4. **不做增益**：不补原文没有的解释、不合并条目、不省略脚注；宁可直译得笨。
5. **区分 revenue / income / profit / gain**：收入 / 收益（利得）/ 利润 / 利得，四个词不能互换。
6. **区分 provision / allowance / reserve**：预计负债 / 备抵（如坏账准备）/ 公积（如资本公积）。
7. **审计意见类型是固定译法**：unqualified 无保留、qualified 保留、adverse 否定、disclaimer 无法表示。**disclaimer 不是「免责声明」**。
8. **附注编号、表格线、缩进层级**保留原结构；OCR 或复制造成的错行要按语义并回。

## 常见坑（按出现频率排序）

| 坑 | 错误做法 | 正确做法 |
|---|---|---|
| 单位 | 直接把 1,284,500 写成「128 万」 | 保留原数 + 表头注明「单位：千美元」 |
| 括号负数 | (742,180) → 742,180 | (742,180) → -742,180 或 （742,180） |
| net | 一律译「净额」 | `net sales` 销售净额；`net income` 净利润；`net of tax` 税后 |
| operating income | 营业收益 | 营业利润 |
| cost of revenue | 收入成本 | 营业成本 |
| material | 材料 | 重要性/重大（`material misstatement` 重大错报；`raw materials` 才是原材料） |
| equity | 一律「股权」 | 权益（报表项目）；股权（指持股比例时） |
| 减值方向 | impairment 一律「减值」 | 转回用 `reversal of impairment` 减值转回，别混 |

## 交付前自检

- [ ] 所有数字差集为空？
- [ ] 术语库里命中的词，译文用的是规定译法？（命中率应 ≥ 90%）
- [ ] 四个合计数验算过：资产总计、负债合计、所有者权益合计、净利润？
- [ ] 单位只声明一次且位置正确（表头，不是每行）？
- [ ] 审计意见段落类型没搞反（保留 / 否定 / 无法表示）？
- [ ] 不确定清单已交用户确认，而不是自己猜？

## 配套工具

- 本仓库 `app/` 下是可执行翻译器（GUI + CLI），内置同一份术语库，术语不一致会自动重译一次。
- 命令行：`FinancialStatementTranslator.exe --cli 报表.docx -o 报表_中文.docx`
- 纯手工场景（不能联网/不能传文件）时，就用 `references/` 里的三份清单在本机做，把术语表和规则念给模型，效果接近。
