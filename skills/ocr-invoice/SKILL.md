# 发票识别工具（08）

把成叠的发票图片压成一张可排序、可求和的字段表，是费用类和采购类审计最耗时的一步。

## 什么时候用

- 报销凭证、差旅票据、供应商发票是拍照或扫描件，需要录成电子台账。
- 要核对某供应商一年开了多少票、某月进项税多少、有没有连号。
- 手工录发票代码、号码、税号容易错位，希望先机器出一遍底稿再人工校。
- 不适合：电子发票的 PDF、OFD 文件本身带文本层，直接从文件读字段更准，OCR 反而会把版面拆乱。
- 不适合：要判发票真伪、查是否作废，必须上全国增值税发票查验平台，本工具只做文字提取，不做查验。
- 不适合：火车票、出租车票、通行费票据、定额发票，票面结构不是增值税发票模板，字段对不上，改用通用 OCR 再人工整理。

## 准备

- 工具位置：`组件/审计署工具/08发票识别工具/02安装包/Windows/发票识别工具/发票识别工具.exe`（官方发布，不在本仓库内）。
- 输入要求：发票的图片（jpg / png / bmp），一票一张图最稳；扫描 200–300 dpi，手机翻拍要平、正、亮。
- 一页多票、票面折叠、有装订孔和阴影的，先裁切修整再投。
- 完全离线：识别引擎和模型都在工具目录内，发票含纳税人信息，离线这点对保密很关键。
- 首次识别要加载模型，界面会停十几秒，不是卡死。
- 输出和留痕在 `resource_invoice/`，记录表在其中的 sqlite3Ai.db，日志在 `log/logging_ai.log`。
- 建议内存 8GB 以上，一次投 50 张以内。

## 操作

1. 解压到本机硬盘，路径不带特殊符号，双击 exe 启动。
2. 添加发票图片，可多选；一批最好同一票种、同一来源，便于后面核对。
3. 开始识别，等进度跑完，中途别关窗口。
4. 在结果表里先看有没有整行空白或明显错位的，再点导出表格，生成 Excel（默认名"增值税发票信息.xlsx"）。
5. 打开 Excel，核对表头字段：机器编号、发票代码、发票号码、开票日期、校验码、购买方与销售方各自的名称/纳税人识别号/地址电话/开户行账号、金额、税额、价税合计、收款人、开票人。
6. 到留痕列表核对张数：投进去几张、识别成功几张，缺的那张单独重投。

## 输出与验收

- 输出物：一份 Excel 台账（一行一张票）+ 可下载的 Word 明细；识别记录在留痕列表和 sqlite3Ai.db。
- 验收要点：逐张核对五个关键字段——发票代码、发票号码、开票日期、价税合计、双方纳税人识别号；这五项错一个，后面的分析全歪。
- 算术校验：价税合计 = 金额 + 税额，用 Excel 建一列差额，不为 0 的必须回原件看。
- 长度校验：发票代码一般 10 位或 12 位，发票号码 8 位，税号 15/17/18/20 位；长度不对就是识别漏位。
- 字符校验：税号里只有数字和大写字母，出现 O、I、S 与 0、1、5 混淆的要回原件确认。
- 名称校验：括号全半角、"( )"与"（）"、多字少字，都会让后面的分组统计分家。
- 批量定位：导出表行数应等于成功识别的张数；用发票号码回查，缺哪个号就是哪张图的问题。
- 重复票：同一张发票重复投会出两行，按发票号码去重后再统计。

## 坑

- 拍照歪斜、有阴影、票面起皱，字段会整体串位，金额跑到购买方那一列，看着"有数"其实是错的。
- 全电发票（数电票）版式与老版增值税发票不同，部分字段可能识别为空，别当成"该票没有此信息"。
- 红字发票金额为负数，汇总时符号看漏会把红冲当蓝票，虚增费用。
- 千分位逗号、"￥"、大写金额与数字金额不一致，是常见错点，必须回原件。
- 发票代码和号码相邻两栏极易互换，核对时看位数而不是看位置。
- 同一供应商名称在不同票上有简称、全称、带括号写法，机器不会统一，需要人工建对照。
- 08 默认占用本机 5011 端口（`resource_invoice/properties.txt` 可改），和其他小工具同时开要错开。
- 识别结果是工作底稿，不能作为"发票真实存在"的证据，原件和查验记录才是。

## 与包内其他工具怎么配合

- 导出 Excel 后，用表格工具做透视、连号检测、供应商汇总、与付款流水比对。
- 与合同、验收单、入库单三方比对时，以发票号码和金额为连接键，别用供应商简称。
- 真伪与状态：拿到号码、日期、金额后上增值税发票查验平台逐张查，查完把结果截图归档。
- 票种混杂（含火车票、出租车票）：先用通用 OCR 或火车票识别分开处理，再并回同一张台账。
- 最终归档：发票原件图、识别台账、查验记录三样放在一起，缺查验记录等于没核过。
